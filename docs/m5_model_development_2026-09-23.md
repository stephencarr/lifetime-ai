# M5 local-model development record — 23 September 2026

## Scope and contract

This is the first implementation of the intended semantic construction, reconciliation, and retrieval path. It is separate from the rule-based diagnostic UI. It runs only against synthetic development data here. Participant UAT remains paused; the repaired 18-case capture preflight is development-only, manual email import is not extractor evidence, and formal G5 is separate. The independent-preflight task was queued but no independent sample has been seen or scored. The live local POC database is private and is not an evaluation corpus. No quarantined G4 v21 holdout or private `.uat` material was used for M5 development or scoring. A later broad test command inadvertently invoked legacy G4 tests that reference the sealed v21 corpus; it was stopped after that was identified. Its four reported failures were historical `uv.lock` manifest mismatches. The potential legacy-test access is recorded here, and no information from those tests was used to tune M5.

An answer is **answered** only when current first-party source evidence supports the requested actor, polarity, scope, and time, and a verifier can point to an exact cited source span. **Conflict** requires incompatible live claims at the same scope, not merely multiple hits. **Needs clarification** covers questions that demand a single choice from compatible scoped claims. Otherwise the path abstains as **uncertain**. Open-ended inventory questions need an exhaustive current-state plan; top-k candidates alone cannot prove completeness. Every durable claim retains a source event, exact quote and offsets, semantic annotation, model identity, and an atomic transition record. These are support and provenance contracts, not guarantees that a model's interpretation is correct.

## Implemented development route

- `llama.cpp` on loopback hosts the pinned Qwen3-8B Q4 GGUF. It proposes structured claims, audits source support, compares new state to candidate state, drafts answers, and checks the answer against cited sources. The same model performs multiple roles, so errors can correlate.
- A pinned BGE small GGUF creates 384-dimensional embeddings locally. SQLite FTS5 and a USearch HNSW index each supply candidates; rank fusion provides a bounded set to semantic reasoning. The index is rebuilt from active canonical SQLite state at startup. Query candidate lookup does not scan all claim vectors, but startup currently does.
- SQLite validates source identity, transition consistency, status and deletion, and commits claims and lexical entries atomically. A failed model or index path abstains. The model has no direct database access.
- The separate `lifetime-model-chat` terminal route requires an explicit new or existing database choice. The original browser route remains diagnostic. Current unauthenticated loopback model servers are for synthetic development only.

## Frozen instrument

`evaluation/m5_model_poc/v0.1` was frozen before the first integrated score. Its hashes and gate thresholds are in `freeze.json` and `criteria.json`. It contains 18 scenarios, 22 user messages, and 22 questions, with expected capture outcomes and claim counts, expected candidate source IDs, answer outcomes, citations, and abstentions. It covers paraphrase, ordinary requests, actor confusion, quotes, hypothetical and uncertain intent, dated experience, scope, negation, duplicates, explicit change, compatible and contradictory claims, deletion, multiple claims, prompt injection, and irrelevant text. The scorer refuses changed hashes and retains full per-step records under `experiments/m5_model_poc`.

## Attempt 1: failed

The pinned Qwen3-8B non-thinking model with initial prompts scored 13/14 clear captures, **6/8 false durable captures**, **0/10 supported answers**, 0/10 unsupported false answers, 10/10 candidate recall on supported questions, 1/1 citation validity among the answers it did issue, and 0/22 deleted-source leaks. Only 26/45 steps passed all item checks. P95 send/ask latency was 37.374 seconds, above the 30-second gate; 73 model calls consumed 18,125 reported tokens. Full records: [attempt-01.json](../experiments/m5_model_poc/attempt-01.json).

The model stored third-party and quoted tea preferences as user claims, a hypothetical flat preference, a one-off climbing event, a prompt-injection request, and an uncertain commitment. It also treated ordinary preference questions as unsupported paraphrases, missed the second claim in a two-claim message, and failed to close an explicitly replaced dark-mode preference. A single commitment was labeled `conflict`. These are product failures, despite perfect candidate recall in this small instrument.

## Attempt 2: failed closed on a schema mismatch

Attempt 2 changed the extractor/source-auditor and answer prompts to state actor, modality, one-off durability, paraphrase, conflict, and supersession examples explicitly. It additionally required an exact cited quote for a supported answer and at least two citations for conflict. The model then emitted `actor: "I"` for first-person claims while the validator required the canonical value `user`; all 14 positive captures abstained. The attempt scored 0/14 clear captures, 0/8 false durable captures, 0/10 supported answers, and 0/10 supported candidate recall. This is a safety-preserving failure but unusable product behavior. Full records: [attempt-02.json](../experiments/m5_model_poc/attempt-02.json).

The third development revision constrained the actor field to the canonical `user` value in the JSON schema and explicitly stated that value in the prompt. A small synthetic probe accepted and answered `I prefer tea`, rejected `Maya prefers tea` at source support, and answered `Please keep replies brief` with a citation. These probes were additional tuning evidence on known cases, not a substitute for the frozen score.

## Attempt 3: major improvement, still failed

Attempt 3 scored 13/14 clear captures, **1/8 false durable captures**, 8/10 supported answers, 0/10 unsupported false answers, 10/10 supported candidate recall, 10/10 citation validity, and 0/22 deletion leaks. Forty of 45 steps passed all item checks. P95 send/ask latency was 29.294 seconds; 72 model calls consumed 24,157 reported tokens. Full records: [attempt-03.json](../experiments/m5_model_poc/attempt-03.json). The model still promoted a dated climbing episode; it extracted both clauses of a two-claim message but the second was rejected as an uncertain relationship to the first; and it represented `coffee after lunch` as a general-scope claim, then failed the after-lunch answer and described compatible preferences as if they had the same scope. Human review also found the conflict answer text (`uncertain`) unhelpfully terse despite a valid conflict outcome and two citations.

The fourth development revision uses a typed durability field and an exact source `scope_anchor` instead of an unconstrained scope description. Episodic/uncertain proposals cannot be promoted; the anchor must occur in the cited source and becomes the stored scope. Reconciliation compares existing claims of the same kind, avoiding a preference-versus-commitment ambiguity within one message. Initial local probes produced `scope_anchor: "after lunch"`, marked the climbing episode `episodic`, and extracted both the preference and Friday commitment. This revision was tuned to known development failures; none of these probes was independent evidence.

## Attempt 4: typed fields did not cure model instability

Attempt 4 scored **6/14 clear captures**, **1/8 false durable captures**, 5/10 supported answers, 0/10 unsupported false answers, 5/10 supported candidate recall, 6/6 citation validity, and 0/22 deletion leaks. Only 29/45 steps passed all checks. P95 latency was 30.697 seconds and 58 model calls consumed 24,354 reported tokens. Full records: [attempt-04.json](../experiments/m5_model_poc/attempt-04.json).

Direct preferences later in the run were rejected by the same model's source-support check, while `Thanks, that helps` was promoted as an ongoing fact that the user is grateful. A separate synthetic probe reproduced both problems: `I prefer tea` was rejected as unsupported; the source verifier called the gratitude message a positive, ongoing commitment. This is a semantic model failure, not an index failure. The first typed-field probes were misleadingly favorable. The local 8B non-thinking configuration is unsuitable for unattended durable capture.

The same pinned 8B weights were also tried with llama.cpp reasoning mode on one direct synthetic preference. Extraction completed, but source support exhausted its 280-token limit without a complete verdict after a long wait. This mode was not run through the frozen instrument and offers no quality claim; its latency is already incompatible with the present 30-second p95 gate at that token budget. The model servers were stopped after the synthetic tests.

## Storage and restart work after the scores

Schema 5 stores each new 384-dimensional embedding as a 768-byte little-endian float16 blob and records its SHA-256 digest, rather than a second JSON vector, in the accepted-proposal audit payload. The retriever still reads legacy JSON vectors from schema 4. Index startup streams live SQLite rows instead of materializing them all, then rebuilds USearch HNSW. Source deletion now looks up only the affected model item IDs through the existing SQLite source index, rather than materializing all live claims. Focused tests cover schema 4-to-5 migration, both vector formats, restart/rebuild, deletion, and model-outage abstention. This reduces storage and peak startup memory but remains an O(N) index rebuild. A separate [synthetic ANN scale experiment](m5_index_scale_2026-09-23.md) now measures the index alone at 10,000, 100,000, and 1,000,000 vectors; it does not measure SQLite startup or semantic retrieval.

## Limits and next gates

The first instrument is broad for development but small. Its automatic answer check assesses outcome and citations, not whether every word of a returned answer is semantically faithful; answer text requires manual review and a stronger labeled answer-content measure. Source support comes from the same model that proposes claims and may repeat its errors. A [separate local NLI candidate](m5_nli_development_2026-09-23.md) failed its frozen false-support gate and remains diagnostic. No calibrated semantic confidence exists; stored confidence is deliberately zero. Current index startup is linear in live claims. The two million-vector ANN configurations recovered 12/32 and 31/32 planted candidates and both failed their frozen recall gate, although query latency was low. Tenant partitioning, persisted ANN maintenance, crash-safe index versioning, data deletion semantics, and local-server hardening remain before participant data. The next semantic iteration needs a more capable local model or an independently validated local entailment/durability component and a larger, newly frozen development set; continuing to tune prompts against these 18 scenarios would overfit. Passing development gates would not authorize UAT by itself. An unseen participant-approved independent preflight and separate G5 comparison are still required.

## Scale path before a product claim

The 128-claim limit belongs only to the retired diagnostic route. The model route uses indexed queries, but its whole-state startup rebuild is still unsuitable as evidence for millions of claims. The next scale iteration should partition canonical state and every search operation by account, persist versioned ANN segments, and record a transactional index-update outbox with each state change. On restart, load a verified segment and replay outbox changes; if the index generation cannot be reconciled with SQLite, block answers until it can. Every hit must be rechecked against canonical live status and source provenance so stale ANN entries cannot leak deleted or superseded claims. Add indexed metadata filters for actor, relation, scope, and effective time; use source-grounded semantic reranking on a measured candidate budget. A broad inventory request must run an exhaustive indexed state query for its declared scope or abstain.

Before asserting that this architecture scales, freeze and run synthetic 10,000, 100,000, and 1,000,000-claim tests with realistic distractors and labeled paraphrase/counterevidence queries. Measure candidate recall, supported-answer accuracy, p50/p95 query and startup latency, peak memory/disk, update and deletion visibility, crash recovery, and model calls. If the 16 GB target cannot satisfy those gates, revise the deployment target or the design rather than citing a small-corpus pass.
